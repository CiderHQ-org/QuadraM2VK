# The refusal surface

Every refusal of something Metal accepts, read from the code: the construction sites of the typed refusals outside tests (`scripts/refusal-surface/refusal_surface.py`, which writes this file; edit its `reach.tsv`, never the tables). Metal's own validation errors (`Invalid`, `InvalidDescriptor`, malformed input) are misuse, not refusals, and are not listed. [`METAL-COVERAGE.md`](METAL-COVERAGE.md) lists the Metal API the runtime has no counterpart for at all.

Columns:

- **What it blocks**: the variant's doc comment, first sentence, and "not scheduled" where the doc says so.
- **Where**: the device condition, from the constructor at its sites: `NotImplemented` and `NotRepresentable` refuse on every device; `needs` names the Vulkan feature, extension, property or limit a device lacks; a driver defect or deviation names the driver. A site that computes its capability says so.
- **Sites**: construction sites (file:line, the first two). "via a helper" counts the places that hand the feature to a function that builds the refusal; "family audit only" is a gap no call refuses, only `supportsFamily:`'s audit (the API is missing: see the coverage map); 0 is a variant nothing builds today.
- **Reach** (hand-kept, `reach.tsv`):
  - `system`: a guest's CoreAnimation, CoreImage or VideoToolbox plausibly reaches it;
  - `app`: a typical Metal app plausibly reaches it from public API;
  - `rare`: public API, but specialized: few apps reach it;
  - `none`: no public API path: malformed or non-Metal input, Apple-private calls, or a cap no valid program of ordinary size meets;
  - `?`: not assessed yet.

Generated at `6cc8b0870`.
